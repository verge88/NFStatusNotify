# Threat model

## Исследуемый эффект

Стенд моделирует последствия принятия AUSF поддельного `NFStatusNotify`:
локальное представление UDM и фактическая маршрутизация меняются, тогда как
состояние, наблюдаемое через NRF, остаётся прежним.

Исследовательский вопрос — не «можно ли сравнить два адреса», а можно ли
надёжно обнаруживать рассогласование при неполных, разновременных и
потенциально недостоверных свидетельствах, не повышая FPR на легитимных
переходных состояниях.

## Границы безопасности

Этот репозиторий намеренно **не содержит**:

- эксплуатационного HTTP/2/SBI payload для уязвимых инсталляций Open5GS;
- скриптов отправки forged `NFStatusNotify` в реальные сети;
- обхода аутентификации, mTLS или сетевых ACL;
- кода поиска уязвимых экземпляров.

Сценарий атаки воспроизводит только наблюдаемый *постэффект* внутри локального
симулятора состояния. Для реального Open5GS рекомендуется получать
телеметрию из авторизованного изолированного стенда и подавать её в тот же
feature/evaluation pipeline.

## Доверительные предположения

Источники рассматриваются независимо:

1. NRF registry view;
2. локальное состояние/кэш AUSF;
3. фактическое направление маршрута к UDM;
4. журнал уведомлений и сведения о подписке;
5. эксплуатационный контекст (recovery/update).

Для каждого источника есть маска доступности. Отсутствие наблюдения не
приравнивается к нормальному значению.

## Положительный класс

Положительным считается временной интервал после момента, когда симулятор
применил forged notification effect и AUSF/route начали указывать на UDM,
не подтверждённый NRF.

Интервалы до атаки в том же run остаются отрицательными, чтобы измерять
раннее обнаружение и задержку.
