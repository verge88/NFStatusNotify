# Locked Stage 6 — PA-TEF as a residual OR extension of consensus_guard

**Preregistered before implementation, benchmarks, inspection or model fitting on new heldout runs.** Previous Stages 3–5 are frozen evidence. Stage 4 over-suppression is a known failure; this study cannot reinterpret it away.

## Scope: six proposals and what is (not) available

Implement and test a new opt-in `patef_residual_guard` which preserves the **existing** `consensus_guard` decisions as hard OR, trains the PA-TEF learned experts/fusion under random run-local source dropout and synthetic source acquisition-age metadata, and calibrates its residual alerts **only on benign calibration points for which consensus_guard did not alert**. Pooled budget `alpha=0.001`. Calibrate *per four-bit source-availability mask*, with the threshold in each group chosen as the more conservative of the pooled and group-specific benign threshold; apply maximum over all training/calibration benign scenario groups where sufficient sample size is present. No test-set calibration. For an empty mask group, unseen mask, or fewer than 20 residual benign calibration samples, residual ABSTAIN (infinite threshold). Expose both the deterministic guard and learned residual decisions separately for auditing.

A positive residual can add to but **never remove** the baseline decision on the identical feature row. That is a per-sample logical invariant, not a distributional guarantee on FPR.

- **Freshness:** source-origin age must derive from already acquired source origin ticks at or before the current observer tick. Treat absent origin metadata as MISSING, never as age=0. In the simulator these are **oracle** metadata, not real trusted source times; real Stage 5 observer-poll completion, cache setup event and pcap capture have different temporal meanings and are NOT interchangeable.
- **Observer identity, UDM response codes, retry/discovery counts:** existing synthetic simulator does not provide these as independently measured / reliable feature columns. Do NOT fake them. Document as missing instrumentation; they cannot support a production claim. Separate optional schema / future instrumentation can be considered but these features will not be invented in this study.
- **Random source dropout:** generate augmented training observations *within run only*, with mask combination selected by deterministic training RNG. Drops and lags apply to source columns consistently, then recompute all temporal features. Train PA-TEF experts with run-disjoint GroupKFold so derived views of a run share the same parent group; no labels, attack onset, future NRF or scenario identifier used as input features. Calibrate learned probability on distinct pristine calibration parent runs; never calibrate on training views. Base PA-TEF default and consensus remain unchanged.
- **Sequential accumulation:** preregister a separate ablation `residual_sequential` with a fixed causal 3-observation rolling max of learned scores **within run**; it is not the primary selected detector. Test without extra parameter tuning; threshold from same benign residual calibration framework on sequential scores. Guard decisions remain immediate by OR.
- **Honest baseline:** consensus_guard uses all available sources, source masks and the present abstaining behavior on missing evidence; compare it under exactly the same degradation views. Also compare old ungated PA-TEF without consensus OR, and residual with (a) no age, (b) no dropout, (c) all proposed options.
- **Worst-case thresholds:** max of per-benign-scenario calibration thresholds and pooled/mask thresholds where group has >=20 samples. This is an empirical robustness heuristic, NOT an adversarial/distribution-free FPR guarantee. The intended target FPR cannot be certified on small runs or correlated per-timestep observations. Bootstrap entire heldout **run_id** groups, never individual temporal samples. If a group has too little heldout benign evidence, report uncertainty rather than success.

## Fixed novel challenge and training partition

- Train source observations: 12 original scenario names and seeds 0..39, 90 ticks. Split original runs into train and calibration **by run_id**, stratified per scenario: seeds 0..29 for train, 30..39 for calibration (no shared parent run). New heldout scenario families / seeds are never fit or calibrated.
- Training views fixed: original, route_lag4, both_lag2 and ausf_lag4, plus deterministic seeded random source masks. For each parent training run, generate the four views; add one seeded dropout copy of an original observed training run, with up to two sources removed. Treat these as augmentation, not independent runs. Only simulation `source_origin_t` may be used for age; keep it marked synthetic-oracle.
- Heldout challenge uses **6 new scenario names** not in earlier Stage 3/4 experiments, seeds 300..323, 90 ticks:
  benign `skew_route_duration4_24` (skew at24, duration4), `skew_ausf_duration10_28` (skew at28, duration10), `recovery_28_48_new` (recovery28..48);
  attacked `route_divergence_at27_new` (attack from27), `cache_divergence_at38_new` (attack from38), `dual_divergence_at31_new` (attack from31). Precommitted real injection of forged network messages is out of scope.
- For **every** scenario, score observer views original, route_lag4, both_lag2, route_lag8, no_ausf, no_route, and no_nrf. Mask degradation is applied to both rule baseline and learned candidate; source-age absent for missing masks. Labels are never touched by view construction.
- Learn and score four detector arms `consensus_guard`, `patef_learned_only` (existing model), `residual_no_age_no_dropout`, `residual_age_dropout`, and diagnostic fixed `residual_sequential` as feasible. No post-inspection sweeps. To avoid multiplication of model fitting costs, the two residual arms may share the same fitted PA-TEF weights only if model input training age feature was disabled consistently; otherwise they need distinct training runs and exact ablation labeling.

## Locked metrics and adjudication

Per detector × view × test scenario × source-mask, report benign count, attack-active count, FP, TP, threshold, sample FPR, sample Recall, detected/total independent attack runs, median detection delay; separate **baseline** and **incremental** alerts and ensure zero overridden guard decisions. Report calibration mask sizes and thresholds, absent-mask abstentions, residual threshold policy, run bootstrap 95% CI (fixed RNG seed 42, 300 bootstrap replicates resampling parent `run_id` within test scenario) of **Recall difference** and benign FPR by view. Warning: 300 reps are descriptive, not a certification of 0.001 tail probability.

**Primary H1: non-regression/safety** only if every view and every test availability mask with benign points has empirical FPR <=0.001, zero overrides (every baseline positive is also hybrid positive), no pointwise Recall drop, no attack-run coverage/delay regression. **H2 incremental ML value** only if H1 passed AND at least two named attack scenarios demonstrate strictly greater pointwise Recall, the pooled heldout attack Recall delta is >=0.01 in at least one stressed view, and its *run-bootstrap 95% interval* has lower bound >0. **H3 missing-source ambition**: for both `no_ausf` and `no_route`, attack Recall >0.62 with per-mask FPR <=0.001, while baseline scores identical test observations. Report H3 independently; passing H3 would not rescue failed H1.

If the baseline already violates the desired 0.001 in a mask/scenario, the OR construction is **mathematically unable** to satisfy that budget there. Report explicit infeasibility `baseline_budget_infeasible=true`, do not tune away baseline rule positives and do not claim H1. Empirical in-sample calibration per scenario/mask does not imply FPR guarantee on previously unseen benign scenarios; source-level conformal validity requires exchangeability assumptions unlikely across scenario shift.
